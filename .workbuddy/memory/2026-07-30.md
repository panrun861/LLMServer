## 本次新发现的两个真 BUG（尚未修复）
1. **中间件抛 HTTPException 变 500**（严重）：`middleware/signature_verification.py:63` 在 Starlette `BaseHTTPMiddleware.dispatch` 内 `raise HTTPException(401)`，中间件层异常不走 FastAPI exception handler → 客户端实际收到 **500 Internal Server Error** 而非 401。实测 `GET /admin/models` 无签名头 → 500。修法：改为直接 `return JSONResponse(status_code=401, ...)`。
2. **security_events.reason_code 溢出**：`signature_verification.py:60` `reason_code=f"missing_headers:{','.join(missing)}"`，6 个头全缺时长度 78 > `schema.sql:135 reason_code VARCHAR(64)` → `asyncpg.StringDataRightTruncationError`，安全审计事件**写入失败**（被 L235 except 吞掉只打日志）。修法：截断 reason_code 或扩列宽。
- 旁证：`/admin/models` 带 `x-local-admin: true` 头可跳过签名校验（middleware L30），实测返回 200 正常。

## 两个中间件 BUG 已修复（signature_verification.py）
- **Bug 1（401→500）**：`dispatch` 不再直接 raise HTTPException，改为把校验逻辑抽到 `_verify()`，外面包 `try/except HTTPException` → `return JSONResponse(status_code, {"detail":...})`。Starlette BaseHTTPMiddleware 内 raise 的 HTTPException 本不走 FastAPI exception handler，会冒泡成 500；现在 401/403/409 等业务码正确透传。
- **Bug 2（reason_code 溢出静默失败）**：`missing_headers:{...}` 拼接 ≈74 字符超 `VARCHAR(64)`，审计写入被 L235 吞掉。改法：reason_code 统一用**短码**（`missing_headers`/`timestamp_expired`/`signature_verification_failed` 等），原拼接的详细信息移入 `detail` JSONB 字段（新增 `detail` 透传参数）；`_log_security_event` 再加 `reason_code = reason_code[:64]` 防御截断，杜绝任何超长写入失败。
- 验证：`py_compile` 通过；真机验证需部署后 curl `GET /admin/models`（无签名头）应得 401 而非 500。改动仅 1 文件 +27/-5 行，未提交（待用户确认是否 commit / 部署）。
- 注：context_length=8192 与实际 vLLM max_model_len=310000 不符属**数据问题**（登记时手填错误），非代码 bug；修正需 `UPDATE models SET context_length=310000 WHERE ...`（待用户拍板是否执行）。

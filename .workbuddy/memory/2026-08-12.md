## Ed25519 签名机制澄清（用户追问"怎么做/对什么签名/能否复用"）
- 签名生成：客户端用 `keys.json` 私钥 `SigningKey.sign(message)` → 64字节 → hex 放 `x-signature`；服务端用注册公钥 `VerifyKey.verify()`（signature_verification.py:164-202，验签在第 187 行）。
- 签名内容（第 176 行）：`{method}\n{request_target}\n{audience}\n{timestamp_str}\n{nonce}\n{body_hash}`，其中 request_target = path + `?query`，body_hash = sha256(body)。6 项绑定，任一改 → 验签失败。
- **签名不可复用（关键澄清）**：数学层 Ed25519 是确定性签名（同输入同输出，可复现）；但业务层每次请求必须换新 nonce + 新鲜 timestamp（±300s 窗口），否则：
  - nonce 已用（第 150 行 NonceRepo.is_used）→ 401 `nonce_reused`（nonce 在验签通过后写 used_nonces 表，第 203-205 行，过期 = timestamp+2×窗口）；
  - timestamp 超窗（第 104 行）→ 401 `timestamp_expired`。
  - 因此测试脚本/Apifox 必须每次发送前动态生成 6 个 x-* 头，不能写死。
- 用户已正确区分：签名=认证+完整性（防伪章），加密=机密性（TLS锁箱），二者叠加非替换。当前项目无 TLS（uvicorn 裸 HTTP :8080），待挂 Caddy/nginx 反向代理补 HTTPS（方案已在前几轮给出，用户未拍板落地）。

## 🔴 更正：用户走的就是 8080，之前"绕过网关"判断错误——实为网关转发 bug

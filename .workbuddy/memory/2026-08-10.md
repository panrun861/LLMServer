## rag-server 与 PLLM 的集成边界（重要澄清）
- `projects/rag/rag-server` 是**完全自包含**的 RAG 后端，自身认证体系（会话 Cookie+CSRF、MySQL `users` 表的 `rag_sk_` Bearer、FastMCP Bearer、Qdrant 向量库）。**全仓库无任何调用 PLLM 管理面(/admin/*)或对话面(/v1/*)的代码，无 Ed25519 签名、无 x-signature 头、无 pllm-tokens/litellm/vllm 引用。**
- 注意 `rag-server/config.py:43` 自身 `port=8080`，与 PLLM 监听端口撞号，易混淆（那是 rag-server 自己的端口）。
- 唯一给 PLLM 管理面签名的代码在 **aitube-pllm 仓库**：`run_api_tests.py`（测试客户端，所有 /admin 调用均签名）与 `AITube-PLLM-Apifox.postman_collection.json`。PLLM 中间件 `signature_verification.py:22` 要求**每个 /admin/* 都验签**（仅豁免 /admin/dashboard Bearer 与 /admin/models + x-local-admin）。
- PLLM token API 设计不对称：`POST /admin/pllm-tokens` 是唯一在 body 里收 `issuer_id` 的接口，且服务端校验 `body.issuer_id == x-issuer-id 头`（token_management.py:47-52）；其余 /admin 接口从验签后的 `request.state.issuer_id` 取身份。这是设计如此，非 bug。
- 用户曾误以为「只有签发 token 才需要加签名参数」，已纠正：PLLM 要求所有 /admin 调用签名；rag-server 本就没有 PLLM 客户端代码。

## PLLM 暴露接口与鉴权盘点（2026-08-10 取证）
- 共 5 类鉴权：① 无鉴权(/health + FastAPI 默认 /docs /openapi.json /redoc)；② Bearer Token(/v1/* 数据平面，inference_gateway BearerAuth 查 tokens 表)；③ Ed25519 签名(/admin/* 控制平面，中间件统一拦截，仅豁免 dashboard 与 /admin/models+x-local-admin)；④ x-local-admin 本地 CLI(/admin/models 全部 6 路由，弱鉴权：仅校验 header 值=="true" 无密钥)；⑤ Dashboard Token(/admin/dashboard 的 snapshot/stream/page，支持头或 ?token= 查询参数)。
- 冲突：`/v1/usage` 被定义两次（inference_gateway.py:526 与 usage_and_audit.py:54），路径重复，FastAPI 后注册(inference_gateway)生效，属代码异味建议清理其一。
- 风险点：/admin/models 的 x-local-admin 无密钥校验=任意客户端加 header 即可管理模型（靠网络层限制兜底）；CORS allow_origins=["*"]+allow_credentials=True 矛盾且宽松；dashboard stream/page 用 ?token= 查询参数传 token（进 URL/日志）；默认 /docs 暴露完整 API schema。
- **x-local-admin 安全定性（用户确认仅调试用、生产不用）**：经读 signature_verification.py:30 确认，豁免条件是 `path.startswith("/admin/models") and headers.get("x-local-admin")=="true"`，**无任何环境变量/来源 IP/密钥门控** → 该后门在代码部署后**常驻生效**，与"生产是否主动使用"无关。攻击者自行加 `x-local-admin: true` 头即可绕过 Ed25519 直接管理模型。修复方向：① 包一层 `settings.allow_local_admin`（仅 DEBUG 为真）环境门控（推荐，改动最小）；② 反代丢弃外部 `x-local-admin` 入站头；③ 彻底删除豁免、/admin/models 统一走 Ed25519（_verify 已能正确处理该前缀）。注意：生产若不含该头，/admin/models 本来就走 _verify 的 Ed25519 路径，故"正常调用"是受保护的，问题仅在绕过通道未关闭。
- **Ed25519 签名测试已跑通（2026-08-10 18:0x）**：新增 `scripts/test_ed25519_admin.py`（托管 venv 装 pynacl+httpx 后可直接 `python scripts/test_ed25519_admin.py`）。实测 `GET /admin/pllm-tokens` 返回 **200**，证明：① L20s 服务器可达；② issuer `aitube-admin`/`key-2026` 已在 `issuers` 表注册且 `is_active`；③ 脚本签名串格式 `METHOD\n{path?query}\n{audience}\n{timestamp}\n{nonce}\n{sha256(body)}` 与 signature_verification.py:164-202 完全匹配（用 `SigningKey.sign(...).signature` 取 64 字节 hex）。签名算法要点：audience 固定 `aitube-pllm`；timestamp 用 ISO8601 UTC（`%Y-%m-%dT%H:%M:%S+00:00`），±300s 窗口；nonce 用 uuid4 hex 且每次唯一（服务端 NonceRepo 防重放）；body 空时 sha256=e3b0c4...（空字节哈希）。后续可测 POST /admin/pllm-tokens 签发（body.issuer_id 须等于 x-issuer-id 头，否则 400）。
